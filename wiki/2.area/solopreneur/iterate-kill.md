# ITERATE / KILL Phase

> 60-day soft check, 90-day hard kill. No feelings, just data.

## Overview

You shipped. Now measure. Pieter Levels killed 70+ projects and only 4 made real money. The key is patience with distribution but ruthlessness with dead products. 60 days gives you time to iterate on marketing. 90 days is the hard limit.

## Decision Matrix

```
Day 30 ──▶ Soft Check: Any paying users? Any traction?
                 │              │
                 │             YES
                 │              │
                 │              ▼
                 │       Keep iterating (distribution takes time)
                 │       Re-launch on PH/HN/Reddit/X
                 │
                 ▼
Day 60 ──▶ Real Check: $100+ MRR?
                 │              │
                 │             YES ──▶ FULL SEND (scale up)
                 │              │
                 │              NO
                 │              │
                 │              ▼
                 │         Last push: price cut, new channel, talk to users
                 │
                 ▼
Day 90 ──▶ Hard Kill: $100+ MRR now?
                 │              │
                 │             YES ──▶ ITERATE (you found it)
                 │              │
                 │              NO
                 │              │
                 │              ▼
                 │         SELL on Trustmrr/Flippa (if any revenue)
                 │         or KILL and move on
```

## Metrics That Matter

| Metric            | Good  | Warning  | Dead  |
| ----------------- | ----- | -------- | ----- |
| MRR (Day 30)      | $50+  | $1-49    | $0    |
| MRR (Day 60)      | $100+ | $10-99   | <$10  |
| MRR (Day 90)      | $500+ | $100-499 | <$100 |
| Paying users      | 10+   | 1-9      | 0     |
| Conversion rate   | >2%   | 0.5-2%   | <0.5% |
| Churn (monthly)   | <5%   | 5-15%    | >15%  |
| Traffic (monthly) | 1000+ | 200-999  | <200  |

## ITERATE (Keep Going)

When data says keep going:

### Priority Order

```
1. Fix what breaks (bugs, errors, payments)
2. Talk to paying users (what do they actually need?)
3. Build the #1 requested feature
4. Re-launch (PH, HN, Reddit, X — new feature = new launch)
5. Improve conversion (landing page, onboarding)
6. More distribution (new channels, niche forums, more X posts)
7. SEO / content (long-term play)
```

### Pieter Levels Patterns (Proven)

| Pattern                        | What                                                             | Why                                                                                 |
| ------------------------------ | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **Build with users**           | Add a feedback box on every page. Ship user requests weekly.     | Users who see their feedback implemented become ambassadors. They promote for free. |
| **Re-launch every 2-3 months** | New feature = new PH post, new X thread.                         | Most people launch once and disappear. Re-launching keeps you visible.              |
| **Niche forums**               | Not just Reddit/HN. Find the horse forum for your horse app.     | Highest conversion channel. People there actually need your thing.                  |
| **Paywall everything**         | Put buy buttons on every feature. If nobody pays → make it free. | Let the market tell you what's valuable. Data-driven pricing.                       |

### What NOT to Do

- Don't redesign (unless conversion is truly broken)
- Don't add features nobody asked for
- Don't switch tech stacks
- Don't build mobile app (yet)
- Don't spend money on ads (organic first)

### Growth Levers (In Order)

| Lever              | Effort | Impact   | When                                 |
| ------------------ | ------ | -------- | ------------------------------------ |
| Talk to users      | Low    | High     | Always                               |
| X build-in-public  | Low    | Medium   | Always                               |
| Price increase     | Low    | High     | When value delivered exceeds price   |
| Feature #1 request | Medium | High     | After 5+ users ask for same thing    |
| SEO / blog         | Medium | Medium   | Month 2+                             |
| Referral program   | Medium | Medium   | 50+ users                            |
| Paid ads           | High   | Variable | Only after organic conversion proven |

## KILL (Stop)

When data says stop:

### Kill Signals (Any One Is Enough)

- $0 revenue after 90 days with distribution effort
- 0 paying users after 200+ signups
- You dread working on it for 2+ weeks straight
- Market is smaller than you thought
- Someone else dominates and you can't differentiate
- MRR hasn't moved in 60 days despite re-launching and iterating

### How to Kill

```
1. Export all data (users, revenue, code)
2. Notify existing users (email, give refunds if needed)
3. List on Trustmrr or Flippa (if any revenue history)
4. If no buyers: archive code, shut down VPS, cancel subscriptions
5. Write a post-mortem (what you learned)
6. Share the failure on X (builds credibility for next launch)
7. Move to next idea → [[idea]]
```

### Kill Is Not Failure

Every kill teaches you something:

- What market NOT to enter
- What feature NOT to build
- What channel NOT to use
- What pricing DOESN'T work

Pieter Levels killed 70+ projects. The ones that survived (Nomad List, Remote OK) make $2M+/year.

## SELL (Exit)

When the product works but you want out:

### When to Sell

- MRR is stable but you've lost interest
- MRR is growing but you want capital for next project
- You've hit a ceiling you can't break through
- Someone makes you an offer

### Pricing Your Product

| MRR     | Typical Price | Multiple        |
| ------- | ------------- | --------------- |
| $50-200 | $1k-5k        | 2-3x annual     |
| $200-1k | $5k-30k       | 2.5-4x annual   |
| $1k-5k  | $30k-150k     | 2.5-3.5x annual |
| $5k+    | $150k+        | 2.5-4x annual   |

### Where to List

| Platform   | Best For                                     | Fees                  |
| ---------- | -------------------------------------------- | --------------------- |
| Trustmrr   | SaaS, micro-products, verified revenue       | Marketplace fees      |
| Flippa     | Larger businesses, content sites, e-commerce | Listing + success fee |
| X / direct | If you have audience, skip middleman         | No fees               |

### What Buyers Want

1. Verified revenue (Stripe screenshots, dashboard access)
2. Low maintenance (document time/week to run it)
3. Growth potential (what they could do differently)
4. Clean codebase (AI-generated docs help here)
5. Tech stack they understand
